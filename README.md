# Anti-Money Laundering (AML) Detection Pipeline

A distributed machine learning pipeline built with PySpark to identify fraudulent transactions and money laundering activities in large-scale financial transaction logs. 

Operating on a synthetic dataset generated by IBM (~32 Million transactions), this project implements end-to-end MLOps practices, including custom feature engineering, handling of severe class imbalance (0.23% laundering rate), and PySpark ML Pipelines.

## Features Engineered

To capture transactional velocity and atypical behavior, the pipeline engineers three temporal and ratio-based features from raw transaction logs:

1. **`Transaction_Duration`**: The time difference in seconds between consecutive transactions made to the exact same bank. Calculated using PySpark windowing `lag` function over a window partitioned by `"To Bank"` and sorted by `"Timestamp"`. High velocity transfers are key indicators of structuring.
2. **`Amount_Ratio`**: The ratio of the paid amount to the received amount. Laundering pipelines often funnel money through intermediary accounts with minimal retention (ratios very close to 1.0).
3. **`Transaction_Frequency`**: Total historical transaction count for each sending bank (`"From Bank"`), signaling if a transaction is originating from a high-frequency hub or a dormant account.

## Installation & Setup

### Prerequisites
- Python 3.10+
- PySpark 3.5+ installed locally (requires Java 8 or 11 configured in path)

### 1. Clone and Create Environment
```bash
git clone https://github.com/jay739/anti-money-laundering-detection
cd anti-money-laundering-detection
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Download and Add Dataset
The dataset used in this project is the **IBM Transactions for Anti-Money Laundering (AML)** dataset hosted on Kaggle. 

1. Download the dataset from Kaggle: [IBM Transactions for Anti-Money Laundering (AML) on Kaggle](https://www.kaggle.com/datasets/ealtman2019/ibm-transactions-for-anti-money-laundering-aml)
2. Extract the archive and place the `HI-Medium_Trans.csv` file under a local `data/` folder in the project root:
```bash
mkdir -p data
# Move the downloaded HI-Medium_Trans.csv to the data/ directory
```

## Usage

The codebase is split into modular execution scripts to run training and evaluation sequentially.

### 1. Training the Model
To train the Random Forest model on the full dataset or a sample fraction (e.g. 5% sample to test locally due to memory constraints):
```bash
# Train on a 5% sample
python src/train.py --data_path data/HI-Medium_Trans.csv --sample_fraction 0.05 --model_dir models

# Train on the full 32M row dataset (requires high-memory Spark config)
python src/train.py --data_path data/HI-Medium_Trans.csv --model_dir models
```

### 2. Evaluating the Model
Score the trained model on the saved test set partition and output performance metrics plus evaluation plots:
```bash
python src/evaluate.py --model_path models/rf_pipeline_model --test_data_path models/test_data.parquet --output_dir plots
```
This saves:
- `plots/roc_curve.png` (Receiver Operating Characteristic curve)
- `plots/pr_curve.png` (Precision-Recall curve, highly useful for checking fraud class performance)
